# 支持矩阵

本文把“代码已实现”“CI 运行过”和“项目已对外承诺”分开记录。没有验收证据的平台或场景，不应被描述为生产支持。

## 运行时与依赖

| 组件       | 当前口径                               | 证据与边界                                                                                                   |
| ---------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Node.js    | 20.19.0 或更高版本                     | `.nvmrc`、`package.json.engines`、CI 使用 20.19；其他版本组合未纳入当前发布承诺                              |
| pnpm       | 10.28.2                                | 根目录 `packageManager`、CI 和发布 workflow 固定该版本                                                       |
| PostgreSQL | 15+                                    | 部署文档要求 15+；CI 使用 PostgreSQL 16；生产容量、升级和恢复仍需部署方验收                                  |
| 浏览器     | Chromium 基础流程 + UI review 结构检查 | CI 安装 Chromium 并运行基础浏览器检查与 mock API UI review；跨浏览器、辅助技术和完整产品闭环尚未形成发布证据 |

## 平台与制品

| 平台                | CLI smoke                                              | Box / 服务运维                                                   | 官方制品与结论                                                                                  |
| ------------------- | ------------------------------------------------------ | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Windows x64         | CI 矩阵覆盖；Windows 本机有 CLI、Web、API 和数据库验收 | 本机安装、启动、备份和恢复已有记录                               | tag workflow 生成 Windows x64 Box 和 CLI 压缩包，并创建 draft Release；维护者人工验收后才可发布 |
| Ubuntu Linux        | Pull request CLI smoke                                 | 适配器已实现，但没有本仓库记录的完整安装、服务管理、备份恢复验收 | 没有 Linux 安装包或发布承诺                                                                     |
| macOS               | Pull request CLI smoke                                 | 适配器已实现，但没有本仓库记录的完整安装、服务管理、备份恢复验收 | 没有 macOS 安装包或发布承诺                                                                     |
| ARM 平台、其他 Unix | 未单独纳入当前 smoke 或发布矩阵                        | 未验收                                                           | 不属于当前支持承诺                                                                              |

## 集成与运营边界

| 场景                     | 当前状态                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------- |
| 本机开发与演示           | Windows 路径已记录；使用 `LOCAL_INSECURE` 和 loopback Origin                             |
| 单实例自部署             | API、Web、PostgreSQL 的部署步骤已提供；真实公网配置、容量和长期运行仍由部署方验证        |
| 多实例、高可用、生产迁移 | 没有 SLA、LTS 或容量承诺；需要独立的备份、恢复、升级和压测证据                           |
| GitHub live              | 提供只读适配器和测试入口；当前没有获准的真实外部仓库/PR 证据                             |
| npm / 多平台包分发       | workspace 包保持 private；当前发布 workflow 不发布 npm，只生成 Windows x64 draft Release |

## 发布渠道与生命周期

| 渠道/版本                 | 当前状态                     | 使用者可依赖的内容                             | 进入下一状态的证据                                      |
| ------------------------- | ---------------------------- | ---------------------------------------------- | ------------------------------------------------------- |
| 默认分支开发快照          | 可自部署、开发用途           | 源码、文档和 CI 结果；不承诺升级或安全响应周期 | 通过待发布 commit 的完整 CI 和发布验收                  |
| Windows x64 draft Release | 自动生成、尚未默认视为正式版 | 可供维护者检查制品、校验和、SBOM 与构建证明    | 安装、升级、卸载、恢复和人工发布审批记录                |
| 正式稳定版                | 当前尚未承诺                 | 只有在发布说明列出的平台、版本和迁移路径       | 管理员设置核验、备份/恢复演练、外部团队验收和维护者签字 |

当前没有 npm、Linux/macOS Box 或 ARM 的官方制品承诺。社区可以自行构建和报告结果，但社区结果必须带有平台、commit、命令和限制，不能自动扩大官方支持范围。正式版也尚未承诺 LTS、固定 SLA 或历史版本自动回移；这些承诺需要在发布说明和安全政策中同时更新。

支持矩阵会随着真实平台验收和发布承诺更新。请在 issue 或 PR 中报告新的平台结果，并注明系统版本、Node/pnpm/PostgreSQL 版本、commit 和可复现步骤。

## 更新支持结论的门禁

只有同时具备可复现的 CI 或现场记录，维护者才应把某个平台从“已实现”提升为“已验证”或“官方支持”。记录至少包含：

- 平台版本、架构、Node.js、pnpm、PostgreSQL 和浏览器版本；
- 待验证的 commit、执行的命令和完整结果；
- 安装、启动、升级、迁移、备份恢复或卸载中实际覆盖的步骤；
- 已知限制、失败场景、责任人和下一次复核日期。

发布说明必须引用对应的 CI run、制品校验和或验收记录。没有这些证据时，只能保留“已实现”或“社区报告”，不能扩大官方支持范围，也不能把单一操作系统上的 CLI smoke 推断为 API、浏览器或生产部署支持。

## 支持范围变更记录

将平台、浏览器、数据库版本或发布渠道提升为“已验证”或“官方支持”时，PR 或发布记录还应说明：

- 变更前后的支持范围，以及仍然不支持的场景；
- 对应 commit、CI run、制品摘要和验收记录；
- 安装、升级、回滚、备份恢复、卸载和安全更新路径实际覆盖的步骤；
- 维护者、备份负责人、下一次复核日期和已接受的限制；
- README、部署说明、安全政策和发布说明是否需要同步更新。

如果没有第二维护者、发布替补或安全响应联系人完成实际确认，支持范围可以继续保持开发版口径，但不能升级为稳定版承诺。
