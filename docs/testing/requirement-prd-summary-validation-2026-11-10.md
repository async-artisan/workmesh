# 需求详情 PRD 概要与分页历史验证

> 2026-11-10。对应[文档主页面方案](../design/document-catalog-ui.md)的需求详情独立切片。实现和静态检查已就绪，冻结后的包级与浏览器行为检查 **NOT_RUN**。

需求详情以真实需求 ID 请求服务端 PRD 概要分页，不再读取项目首 50 份完整文档后在浏览器筛选。页签只采用匹配项目和需求的成功 `total`；未知、读取中、失败或 stale 显示 `—`。页签未打开时仅读取一页概要，历史、metadata 和正文均不预取。

打开页签后按 50 份切页；用户显式展开一份文档时才读取唯一历史，按 50 条续页。当前发布独立于已加载历史，用户请求后以准确发布修订 ID 读取 metadata，使用编码后的规范评审路径。列表和历史读取保留临时失败、权限清理、版本或 total 变化，以及切需求、切文档和离开页签的迟到隔离。通用按钮如实标明“打开项目文档页”，携带当前项目。

浏览器局部 fixture 使用 107 份 PRD，项目首 50 份属于需求 B，需求 A 的准确总数为 57，目标文档位于项目首屏外并含 123 条修订、seq2 当前发布及 122 个候选。26 个场景覆盖两种宽度、目录 50/7、历史 50/100/123、当前发布与第二页候选的准确评审、503/403/409/total 变化、跨需求迟到及键盘和溢出。默认拒绝旧完整读取、正文读取及写入；这是受控交互证据，不是实际数据库或 HUMAN 批准。

实现者的四文件 Prettier、定向 ESLint 和 Web `tsc --noEmit` 已通过；未执行的单元、生产构建与 Chromium 不能以这些静态结果替代。先与已通过 Knowledge 及概要 API r3 源码整合冻结，再运行完整 Web 和生产 Chromium fixture；完整 `pnpm verify`、新制品和远端门禁仍独立验收。
