# 旧评审链接兼容验证

> 2026-11-10。原始问题见 [PRD 主页面验证](prd-summary-history-validation-2026-11-10.md) r1 的准确评审跳转失败。全局兼容修复已完成静态检查，行为复验 **NOT_RUN**。

旧地址 `/reviews?id=<reviewId>` 由 App 的 `Navigate replace` 转到规范详情路径。项目边界同时将该地址当成项目列表，已加载项目时又在 effect 写入 `projectId`；两个导航竞争，后一次可覆盖规范跳转，使旧地址保留但主区域空白，也不读取评审。

限定修复让带非空 `id` 的旧入口跳过列表项目参数补写，保留既有规范跳转。空 `id` 仍按普通评审列表处理。单元场景显式预载项目以暴露导航竞争，核对无参数、相同/不同项目、编码 ID、空 ID、规范路径及 replace 后退行为。

14 个 Chromium fixture 场景在 1440/390 宽度下核对准确评审、metadata 与可见正文、只读槽位、前进/后退、编码斜线 ID 与刷新、403 及空 ID 列表。默认拦截写入与旧完整文档读取，局部 fixture 不改变共享数据或伪造人工批准。

三个文件的 Prettier、定向 ESLint、Web 类型检查，以及新 spec 的单文件严格/noUnused 类型检查已通过。这些静态结果不替代单元、生产构建或浏览器行为；后续与其余消费者整合冻结后执行，完整门禁、新制品及最终远端 CI 单独记录。
