## 采用的开源经验

- Backstage Software Templates：参数前置收集、约束选择、分步执行、结果直达。
- Gerrit Attention Set / Review UI：现在轮到谁、基于审查轮次的版本比较。
- GitLab Discussions / Test Reports：可解决并重开的评审问题、测试结果与批准分离。
- OpenProject Relations：双向阻塞对象及可进入的关系。
- GitHub CLI Run View：稳定对象编号、结果与失败诊断可继续查询。
- Supabase Self Hosting：部署者声明可信地址，配置、启动和检查生命周期清晰。

对应官方材料及本项目采用范围（2026-11-09 核对）：

| 官方来源                                                                                                               | 在 WorkMesh 中落实的行为                                               | 保留的边界                                                                  |
| ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| [Backstage Writing Templates](https://backstage.io/docs/features/software-templates/writing-templates/)                | 参数先校验、再签发一次性接入码，分步呈现授权、绑定、角色资源和后续任务 | 参数预检不创建流程实例，也不替用户完成本机 checkout                         |
| [Gerrit Attention Set](https://gerrit-review.googlesource.com/Documentation/user-attention-set.html)                   | 明确当前责任人、本人可行动项及评审来源轮次                             | 借鉴责任归属思路，没有引入另一套 attention 状态；本次该官方页面网络读取超时 |
| [GitLab Comments and Threads](https://docs.gitlab.com/user/discussions/)                                               | 独立问题、追加回应、解决/重开、跨轮次追溯                              | 问题解决不改变批准状态，当前精确审批人权限仍由 WorkMesh 校验                |
| [OpenProject Relations](https://www.openproject.org/docs/user-guide/work-packages/work-package-relations-hierarchies/) | 双向显示前置阻塞和受影响后续任务、责任人及定位动作                     | 当前只呈现现有流程的直接依赖，不增加任意关系编辑器                          |
| [GitHub CLI Run View](https://cli.github.com/manual/gh_run_view)                                                       | 稳定操作编号、真实评审编号、可继续查询的状态与失败诊断                 | 未知写入结果先核对原收据，不自动创建新的业务操作                            |
| [Supabase Self Hosting](https://supabase.com/docs/guides/self-hosting/docker)                                          | 配置可信外部地址、区别环境检查、启动、服务就绪与日志诊断               | 本机存活和数据库就绪均不等同于项目授权、业务发布或恢复验收                  |

验收证据矩阵也沿用 [GitLab Unit Test Reports](https://docs.gitlab.com/ci/testing/unit_test_reports/) 中“检查结果帮助审阅”的取舍：只把显式关联验收 key 的质量包证据映射到条款，显示来源、结果、位置与版本；提交者报告通过和外部引用保持待人工核验，正式决定仍走原评审槽位。
