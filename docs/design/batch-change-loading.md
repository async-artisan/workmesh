# 工作台批量变更确认按需加载

> 2026-11-10。对应 P2 首页体积后续切片；工程记录不替代平台需求、正式批准或发布证据。r4 本地切片已通过，失败尝试与范围见[验证记录](../testing/batch-change-loading-validation-2026-11-10.md)；原首页体积预算仍未达。

用户进入首页时无需下载批量变更确认的执行及结果展示代码，点击批量入口后才加载。当前快照、选中集合、筛选、单条确认和页面刷新仍由 Workbench 管理；独立组件管理一轮批量确认的提交锁、进度、结果和显式重试。只做现有功能的有界提取，不改变权限、版本、幂等或 HUMAN 批准链。

预览来自当前快照，不是服务端 preflight。确认按目标自己的版本逐项发送，首错停止，其余标记未处理；成功项立即从选择移除。重试时读取最新快照，只发送仍存在的失败或未处理项，使用最新版本，保留成功记录。刷新失败仍保留结果与错误，主页保持 stale 提示；关闭后再次打开按现有语义开始新一轮。

加载期间可关闭，失败显示重试与刷新；迟到下载不能重开窗口。正常执行期间禁止按钮、遮罩和 Escape 关闭，防止丢失结果。同步锁防止 React 更新前连续点击启动第二轮；组件卸载后停止后续请求和页面回调，已发出的确认请求仍可能在服务器完成。以当前 recipientId 标记处理行，避免重试带入成功结果后进度索引偏移。

选择沿用 WorkbenchDialogs 的独立动态组件与 Modal，避免再建一套窗口框架。仅移 JSX 会保留首页执行逻辑，因此一起移动这轮流程；`changeApi`、错误格式化及 Modal 仍由其他首页功能使用，实际体积改善必须重新计量。上轮通知切片首页为 284227 B raw，原 `<200000 B raw` 目标继续开放。
