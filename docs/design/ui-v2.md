# WorkMesh UI v2：成熟控制台规范

> 版本：v2.0 · 日期：2026-11-02 · 状态：已落地
> 目标：从“把 API 表格化”的后台，收敛成一套成熟、可长期维护的协作控制台。
> 实现：`apps/web/src/ui-v2.css`，在 `index.css` 之后加载，覆盖旧样式而不重写全部历史 CSS。

## 1. 判断标准

一套“像成熟系统”的界面，至少满足：

1. **有边界**：内容有最大宽度，不在 2K/4K 屏上无限拉伸。
2. **有层级**：导航、页面标题、区块、表格、辅助信息五级清楚。
3. **有密度**：14px 正文、13.5px 表格、12px 辅助信息，而不是全站 11–12px。
4. **有节奏**：8px 网格、统一的圆角与间距，不用随手写的 margin。
5. **有状态**：主按钮、次按钮、危险按钮、禁用、空态、加载态一致。
6. **能扫读**：表格行高、对齐、状态标签、数字列固定规则。

## 2. 整体骨架

```text
┌────────────────────────────────────────────────────────────┐
│ 顶栏 60px：品牌 / 通知 / 账号                              │
├──────────┬─────────────────────────────────────────────────┤
│ 深色侧栏  │ 内容区：最大 1480px，居中留白                    │
│ 236px    │ 页面标题 + 描述 + 操作                           │
│          │ 卡片 / 表格 / 看板 / 工作台                      │
└──────────┴─────────────────────────────────────────────────┘
```

- 侧栏深色 `#0f172a`，形成稳定骨架；内容区浅灰 `#f4f6fa`，白卡片承载信息。
- 内容区**不再限制固定最大宽度**，用 24–48px 的视口留白铺满可用空间；长文/表单各自限制阅读宽度，而不是把整页压成中间一条。
- 侧栏宽度 236px，顶栏 60px；与内容区共用同一套间距。

## 3. 设计 token

| 类别               | 值                                          |
| ------------------ | ------------------------------------------- |
| 应用底             | `#f4f6fa`                                   |
| 卡片 / 表面        | `#ffffff`                                   |
| 描边               | `#e3e8ef`，强描边 `#cbd5e1`                 |
| 主文字             | `#0f172a`；次文字 `#475569`；辅助 `#7b8798` |
| 主色               | `#2563eb`，hover `#1d4ed8`                  |
| 成功 / 警告 / 危险 | `#15803d` / `#b45309` / `#dc2626`           |
| 圆角               | 8 / 12 / 16                                 |
| 阴影               | 1px 轻投影；hover 用 6px 18px 中投影        |
| 字体               | Inter + 系统中文字体；正文 14px             |

## 4. 页面规则

### 工作台

- 四类读数卡一行铺满；数字 32px、标签 13px、提示 12px。
- 筛选/搜索/排序在同一行，窄屏换行；不再竖向堆叠。
- 每行：类型、需求编号/标题、角色/等待时长/证据、主操作；左色条区分待办类型。
- 空态用一个居中的虚线卡片，不撑满整屏。

### 任务看板

- 5 列等宽铺满内容区；窄屏切换为 260px 横向滚动。
- 列底色 `#f8fafc`，卡片白色 + 轻描边；不再出现右侧整块空白。
- 卡片只保留标题、角色、状态、动作。

### 需求与表单

- 表单最大宽度 760px；标签在上、输入在下，不再横向拉满全屏。
- 卡片内边距 20px；输入高度 38px；主按钮 36px。
- 列表表格：表头 12px、正文 13.5px、行高 13px 上下留白；操作列右对齐。
- 2K/4K 屏内容居中，不再从左贴到右。

### 需求详情

- 详情头、7 段门禁、Tab、双栏内容保持同一内容宽度。
- 门禁与 Tab 在同一视觉层级；右栏用于“下一步/门禁清单”，不抢主内容。
- 公文式长文用纸面 `paper-content`；决定页 diff 用行级颜色。

### 按钮与状态

| 类型     | 规则                                                  |
| -------- | ----------------------------------------------------- |
| 主按钮   | 蓝底白字，36px 高，8px 圆角，单屏只出现一个主操作     |
| 次按钮   | 白底 + 描边，hover 浅灰                               |
| 危险按钮 | 白底红字红边，hover 浅红，不默认填充红                |
| 禁用     | 浅灰底、灰字、无阴影，明确不可点                      |
| 状态标签 | 22px 高、8px 字号 11.5px、浅灰底 + 描边；颜色只做辅助 |

## 5. 响应式

| 断点      | 行为                                            |
| --------- | ----------------------------------------------- |
| >1280     | 4 列读数、5 列看板、内容铺满并保留 24–48px 留白 |
| 1100–1280 | 读数 2 列、看板横向滚动                         |
| 960–1100  | 内容内边距 24px                                 |
| ≤960      | 侧栏收起，内容全宽                              |
| ≤720      | 读数 1 列、筛选全宽、表格收紧、表单内边距 16px  |

## 6. 实施方式

- 新增 `ui-v2.css`，在 `index.css` 之后加载；只覆盖 token、骨架、页面级组件，不删除历史样式。
- 现有页面 class 不变，避免大范围改 TSX；后续清理旧 CSS 时再逐块合并。
- 新页面必须使用同一套 token、按钮、卡片和表格规则；不得再引入第二套视觉语言。
