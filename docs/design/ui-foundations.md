## 1. 设计令牌接入方式

### 1.1 样式加载顺序

`apps/web/src/main.tsx:5-11` 的实际顺序：

```text
index.css → ui-v2.css → ui-v3.css → ui-v4.css → styles/tokens.css → styles/feedback.css
```

约定：

- 旧四份 CSS 仍按原顺序加载，页面既有外观不变；`tokens.css` 与 `feedback.css` 放在最后，但新组件并不依赖"谁覆盖谁"，因为 `--wm-*` 是不与旧变量重名的独立命名空间。
- 新组件只使用 `--wm-*`，不读取 `--accent`、`--bg-app`、`--text-*`、`--radius-*`、`--shadow-*` 等旧主题变量；这样后续调整、收敛旧主题时不会连带改变新组件。
- 旧 CSS 保留、不迁移、不删除。v2 的布局与响应式规则、v3 的结构与深色视觉、v4 的亮色覆盖关系都继续生效，直到后续阶段逐页收敛。

### 1.3 使用约定

- 新组件和后续新页面只写 `var(--wm-*)`；不直接写十六进制/rgba 色值，不读取旧 `--accent` 等变量。`feedback.css` 已按此实现：`.wm-*` 类只引用 `--wm-*`（`feedback.css:5-9`）。
- 类名统一 `wm-` 前缀，避免命中 `index.css`、`ui-v2.css`、`ui-v3.css`、`ui-v4.css` 中已有的通用类（如 `.page-card`、`.status-tag`）。
- 旧页面继续使用旧类与旧变量，不做迁移；需要公共反馈时使用 `PageState` / `EmptyState` / `ErrorState` / `StaleDataBanner`，不复制一套新的视觉。
- 新增令牌只加在 `tokens.css` 的 `:root`，并在本文档补一行；不要覆盖或重定义旧变量名，避免影响存量页面。
- 焦点：可交互控件统一 `:focus-visible` 描边（`feedback.css:32-35`、`feedback.css:231-234`）；不依赖颜色本身表达状态（`feedback.css:8`）。
- 动效：遵守 `prefers-reduced-motion`，加载动画在减少动态时降速（`feedback.css:118-122`）。

### 1.4 字号约束

| 场景                         | 令牌                                           | 下限               |

| 正文、表格内容、按钮         | `--wm-text-md` = 14px                          | 正文默认 ≥ 14px    |

公共反馈组件已遵守：`feedback.css` 只使用 12/13/14/16px 四档（`feedback.css:100`、`108-109`、`161-162`、`169`、`214`、`226`、`243`、`282`、`289`），没有 9px/10px 的正文用法。新组件最低字号为 12px。

## 3. 反馈语义规范

### 3.1 场景与组件的对应关系

| 场景                         | 组件 / 位置                                                     | 语义                                           | 可访问性                                                         | 禁止                              |
| ---------------------------- | --------------------------------------------------------------- | ---------------------------------------------- | ---------------------------------------------------------------- | --------------------------------- |
| 短暂成功、非阻塞提示         | `Toast`（`store/toast.ts` + `components/ToastHost.tsx`）        | 操作已完成或信息性提示，3.6 秒自动消失         | `role="status"`、`aria-live="polite"`、可手动关闭                | 作为页面错误的唯一反馈            |
| 页面无法正常加载             | `PageState kind="error"` → `ErrorState`                         | 请求失败且没有可展示数据，页面主区域进入错误态 | `role="alert"`、`aria-live="assertive"`、标题+说明+折叠详情+重试 | 显示为空数据；只弹 Toast          |
| 表单字段错误                 | 字段附近的内联提示（后续表单复用）                              | 单个字段校验或局部提交失败，保留用户输入       | `aria-invalid`、`aria-describedby` 关联字段                      | 把字段错误只放到 Toast 或页面顶部 |
| 页面仍可用但数据过期         | `StaleDataBanner`（`PageState kind="stale"`）                   | 本次刷新失败，保留上次成功数据，页面可读可操作 | `role="status"`、黄色/橙色警示、不是错误红                       | 当成错误红；写成"API 已连接"      |
| 页面无法继续操作（渲染崩溃） | `ErrorBoundary`（`components/ErrorBoundary.tsx`）→ `ErrorState` | React 渲染异常导致页面不可用，技术堆栈折叠     | 提供"重试渲染"与"刷新页面"                                       | 吞掉异常只留空白                  |
| 无权限                       | `PageState kind="forbidden"` → `EmptyState variant="no-access"` | 权限边界，不诱导反复重试                       | `role="status"`、说明联系管理员                                  | 显示成系统错误或空数据            |
| 成功但无数据                 | `PageState kind="empty"` → `EmptyState`                         | 请求成功，确实没有记录/匹配/尚未产生内容       | `role="status"`、给出下一步或等待说明                            | 用错误态伪装空态                  |

`PageState` 的 kind 定义见 `PageState.tsx:18-24`；`toPageLoadState` 把 403 映射为 `forbidden`，其他错误映射为 `error` 并保留 `formatApiError` 的 detail 与 requestId（`PageState.tsx:162-175`）。

### 3.2 Toast：短暂、非阻塞

- `toast.success/error/info` 三种 tone（`store/toast.ts:3-9`、`31-35`），统一 3600ms 自动消失（`store/toast.ts:24-26`）；`ToastHost` 渲染 `role="status"` 与 `aria-live="polite"` 的容器（`ToastHost.tsx:10`），关闭按钮有中文 `aria-label="关闭提示"`（`ToastHost.tsx:14`）。
- 适用：保存成功、复制成功、会话过期后的跳转提示等"说完即可"的信息；错误类 tone 只能用于**非阻塞**且页面上已有可见失败状态的操作（例如局部保存失败但页面仍可操作）。
- 不适用：页面首次加载失败、路由数据失败、空态原因、过期数据提醒。Toast 会消失，不能承担"用户需要据此判断页面是否可用"的职责。
- 多个 Toast 不应堆叠成错误中心；页面级错误必须落到 `ErrorState` 或 `StaleDataBanner`。

### 3.3 页面错误：`PageState` → `ErrorState`

- 触发条件：请求失败（`ApiError` 或未知异常）且**没有可展示数据**。`PageState` 的 `error` 分支渲染 `ErrorState`（`PageState.tsx:114-127`）。
- 展示层级：用户先看到可理解的中文标题与说明（`ErrorState.tsx:62-70`），技术细节（`formatApiError` 输出的 `[CODE] message` 与 `requestId`）收在"查看详细信息"的折叠区（`ErrorState.tsx:71-75`，文案见 `ErrorState.tsx:73`）。
- 重试：提供 `onRetry` 时渲染主按钮，`aria-label` 默认取 `retryLabel`（默认文案"重试"，`ErrorState.tsx:79-89`）；`PageState` 同时支持一个次操作（`PageState.tsx:125`）。
- 错误码与 requestId 不得删除：`ApiError` 保留 `status/code/details/requestId`（`client.ts:11-22`），`formatApiError` 拼出 `[code] message · requestId <id>`（`client.ts:160-166`），`toPageLoadState` 只透传不丢弃（`PageState.tsx:166-174`）。
- 403 不是普通错误：`toPageLoadState` 返回 `forbidden`，页面显示无权限空态，不诱导重试（`PageState.tsx:168-173`）。

### 3.4 字段错误：留在字段附近

- 表单校验或字段级提交失败时，错误信息应紧贴对应控件，保留用户已输入内容，并允许用户修正后重试；不得把字段错误只显示成页面级 Toast。
- 使用原生可访问性关联：控件设置 `aria-invalid="true"`，错误文本通过 `aria-describedby` 指向字段的错误元素；错误文案用中文说明"哪个字段、为什么错、如何改"。
- 若后端返回字段级错误码/`details`，在字段附近显示可读说明；完整 `code`/`requestId` 仍保留在页面级技术详情中（与 3.3 一致），不得因为改为内联展示而丢弃。
- 字段错误与页面错误分开：不要因为一个字段失败就把整个页面替换成 `ErrorState`，也不要在字段错误时清空列表数据。

### 3.5 数据过期：`StaleDataBanner`

- 使用条件：页面已有上次成功数据，本次刷新失败；页面仍可阅读和操作。`PageState` 的 `stale` 分支先渲染 `StaleDataBanner`，再渲染 `children`（`PageState.tsx:140-153`）。
- 默认文案与格式：标题"当前显示的是上次成功数据"，有 `updatedAt` 时追加" · HH:mm"（`StaleDataBanner.tsx:62-64`，时间格式化见 `StaleDataBanner.tsx:4-12`）；说明默认"本次更新失败，数据可能已经过期。"（声明于 `StaleDataBanner.tsx:40`，渲染于 `StaleDataBanner.tsx:65-67`）。
- 视觉：使用 `--wm-color-warning-*` 黄色/橙色警示（`feedback.css:257-292`），不是错误红；`role="status"` 而非 `alert`，避免打断屏幕阅读器（`StaleDataBanner.tsx:29-37`、`55-58`），这是过期提示与页面错误的语义分界。
- 支持 `onRetry`，按钮为 `wm-button--warning`；默认 `retryLabel="重试"` 时 `aria-label` 为"重试更新数据"，自定义 `retryLabel` 时 `aria-label` 使用该文案（`StaleDataBanner.tsx:69-79`）。
- 过期只说明"数据新鲜度"，不说明连接状态：即使 API 连接可用，数据仍可能过期；即使数据是最新的，也不代表页面服务或业务数据已同步。

### 3.6 严重错误：`ErrorBoundary`

- 捕获 React 渲染异常；出错时复用 `ErrorState`：标题"页面渲染出错"，说明"页面组件渲染时发生异常，当前页面无法继续操作。可以重试渲染，或刷新整个页面。"，`detail={error.stack ?? error.message}` 折叠在"查看详细信息"中（`ErrorBoundary.tsx:23-36`）。
- 操作：主按钮"重试渲染"清空 error state 让子树重新渲染；次按钮"刷新页面"调用 `window.location.reload()`（`ErrorBoundary.tsx:26-35`）。
- `App.tsx` 用 `ErrorBoundary key={location.pathname}` 包裹路由内容（`App.tsx:209-214`、`App.tsx:472`），路由变化时重置错误边界。
- 边界：`ErrorBoundary` 只处理渲染崩溃，不处理请求失败；请求失败必须交给 `PageState/ErrorState`。`ErrorBoundary` 已改走 `ErrorState`，因此同样具备 `role="alert"`、折叠技术细节和与页面错误一致的视觉，不再使用旧的 `page-card`/`eyebrow` 类。

### 3.7 硬性规则

1. **请求失败不得显示为空数据。** 只有请求成功且确实没有数据时才进入 `empty`；请求失败进入 `error`；失败但保留旧数据进入 `stale`。空态和错误态的外观、文案、可访问性角色都必须不同（`PageState.tsx:99-127`、`140-153`）。
2. **不得把所有错误改成 Toast。** Toast 会消失，不能作为页面错误的唯一反馈；页面级失败必须在页面主区域留下可理解、可重试的持久提示。
3. **不得删除现有错误码和 requestId。** `ApiError` 的 `code/details/requestId`、`formatApiError` 的输出格式、`ErrorState` 的折叠详情都保留；技术信息只能"折叠"，不能"丢弃"。
4. **"API 已连接"不等于页面服务可用，也不等于业务数据已同步。** 三者分开表达：
   - API 连接：只说明网络/接口可达；
   - 页面服务可用：需要页面数据加载成功、关键操作可用；
   - 业务数据已同步：需要数据时间戳/刷新结果支撑。
     页面上不得用"API 已连接"暗示后两者；数据新鲜度只由 `StaleDataBanner` 的 `updatedAt` 与"本次更新失败"文案表达。
5. **过期不是错误。** 数据过期时页面可用，用黄/橙警示与 `role="status"`；不要用错误红、`role="alert"` 或"页面加载失败"标题。
6. **不能只靠颜色区分状态。** 每个状态都有图标、标题和完整中文文案；错误/警告色只是辅助（`feedback.css:8`，组件内图标均 `aria-hidden`，文字承担语义）。
