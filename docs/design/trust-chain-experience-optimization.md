## 取舍与异常

- 输入诊断复用创建快照的输入解析，诊断模式可收集问题，创建模式继续遇到不满足条件即拒绝。缺失不等于无权查看；未确认读取权限的文档和修订不返回标识。
- 首先复用 CLI 操作收据和状态持久化。服务端会话不作为先决条件；不能用最新版本替代 Agent 实际读取的版本。
- 下游可达数量不称作关键路径，也不承诺处理后全部解锁。所有派生视图只解释正式事实，不新增批准路径。
- 代码证据的签名失败不是可信业务事实；诊断记录不得把未验签载荷绑定成已采信证据。
- 发布报告复用已有检查，不以文档勾选或本机检查替代最终候选远端结果及人工批准。

- O1：已实现并完成定向验证。`inspectInputs` 收集结构化问题与可公开定位，Web 展示责任和动作，CLI 支持只读 `context --task <id> --inspect`。多项缺失、权限边界、可选输入和零写入已由单元、隔离数据库和浏览器用例验证；完整联合门禁待后续统一执行。执行结果与限制见 [验证记录](../testing/trust-chain-experience-validation-2026-11-10.md)。
- O2：已实现收件人任务指引、角色/用户范围与当前状态解释；定向 API、数据库、Web、CLI 与浏览器验证见验证记录。
- O3：已实现需求当前基线完整性与正式事实时间线；当前有效、历史保留、撤回、撤销和来源分开显示。正在完成最终联合复核。
- O4：已实现从原操作回执重建的本地执行状态及未知结果恢复；认领/交付 API 补充原提交准确版本。执行方法见 [CLI 执行状态](../cli-execution-state.md)。
- O5：已实现完整关联实例的下游影响和新增前置就绪数；ACK、基线变更、多审批槽及暂停/退役分别解释。定向行为证据已通过。
- O6/O7：代码证据分段诊断、角色版本/安装/实际资源差异正在完成定向验证。
