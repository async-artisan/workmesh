# WorkMesh Web 界面规范

> 当前默认外观：亮色指挥台（由 `ui-v4.css` 覆盖主题 token）。
> 实际样式以 [ui-v2.css](../../apps/web/src/ui-v2.css)、[ui-v3.css](../../apps/web/src/ui-v3.css)、[ui-v4.css](../../apps/web/src/ui-v4.css) 为准；本文件记录它们共同形成的当前规范。

## 样式层与主题

Web 入口按 `index.css → ui-v2.css → ui-v3.css → ui-v4.css` 的顺序加载样式。三个 UI 样式文件仍在用，不应按本规范合并而删除：v2 提供基础布局、组件密度与响应式规则；v3 加入指挥台结构和深色信号视觉；v4 保留该结构并覆盖为当前默认的亮色主题。

目前没有可切换的主题选择器。v3 的深色 token 不代表用户可选的夜间模式；如要提供主题切换，需要单独实现并验证切换行为。

## 当前视觉 token

| 用途                   | 当前值                            |
| ---------------------- | --------------------------------- |
| 页面底色               | `#f3f6fb`                         |
| 导航背景               | `rgba(255, 255, 255, 0.92)`       |
| 面板与表面             | `#ffffff`；悬停 `#f1f5f9`         |
| 描边                   | `#e2e8f0`；强调描边 `#cbd5e1`     |
| 主要 / 次要 / 辅助文字 | `#0f172a` / `#475569` / `#7b8aa0` |
| 主信号                 | 青色 `#0891b2`；悬停 `#0e7490`    |
| 成功 / 警告 / 危险     | `#059669` / `#d97706` / `#e11d48` |
| 圆角                   | 小 `7px`、中 `10px`、大 `14px`    |

正文基准为 `14px`。表格和辅助信息可以更紧凑，但要保留清晰层级和可读对比；状态色用于辅助辨识，不能只靠颜色表达状态。

## 页面结构与组件

- 导航、页面标题、区块标题、主体内容和辅助说明保持明确层级；页面留白随视口变化，避免宽屏内容无限拉伸，也避免表单和长文横向铺满。
- 工作台先呈现待处理信号，再显示筛选与待办列表。读数卡、搜索/筛选、分组列表和主操作使用一致的间距、边框和焦点状态。
- 看板保持只读执行视图；需求详情以门禁进度、Tab 和证据内容组织信息。沿用现有页面结构和组件，不另造一套颜色、按钮或卡片规范。
- 表单标签置于控件上方，输入、按钮、卡片和表格采用统一尺寸；主操作应醒目，危险操作使用红色边框或文字明确区分。
- 窄屏下导航、统计卡、筛选项和列表应按样式中的断点收拢或换行；交互控件不能因压缩而难以操作。

## 信号、编号与动效

青色表示当前关注或需要处理的信号；蓝色用于审批类信息，琥珀色用于变更，绿色用于可继续或成功，红色用于危险状态。需求编号、工作流键和摘要等机器标识可以使用等宽字体，正文仍优先可读性。

扫描、脉冲和渐变只用于当前状态、焦点或关键操作。避免大面积发光、装饰性位移和高频动画；遵守 `prefers-reduced-motion`，减少动态效果。

## 后续维护

- 新页面复用当前 token、按钮、卡片、表格和响应式规则。
- 只有在代码实现并验证后，才把主题切换、夜间模式或新的视觉能力记录为现状。
- 如规范文字与 CSS 不一致，以 CSS 和页面实际行为为准，并同步修订本文件。

## 已核对的后续事项

以下事项来自已归档的 Web 改版方案，已按当前代码重新核对：

- **主题切换与夜间模式**：当前只有 v4 亮色默认主题；v3 是已加载的深色视觉层，但没有用户可切换的主题选择器。
- **设置 IA**：当前导航提供角色/ACL、设备授权和用户中心入口，没有独立的 `/settings` 页面。归档方案中的设置页仍是信息架构提案。
- **定时邮件提醒**：当前实现支持用户手动发送邮件摘要；定时触发需要外部 cron 或调度器调用接口，仓库内没有内置调度任务。
- **完整浏览器闭环、跨浏览器和无障碍验收**：属于当前验证工作，详见 [阶段状态](../phase-status.md) 和 [开发计划](../dev-plan.md)，不应从历史设计稿推断为已完成。

更广的协议和产品待实现项（例如澄清服务、15 章 PRD 与原型验收）统一维护在 [开发计划](../dev-plan.md)，不在本 UI 规范重复。
