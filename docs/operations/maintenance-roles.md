# 维护职责与交接矩阵

> 本文件描述需要被真实人员或团队认领的职责，不自动授予任何 GitHub、云平台或生产权限。未确认的人员保持“待管理员指定”，禁止填写虚构账号。实际权限应遵循最小权限，并由管理员在受控系统核验。

## 稳定版发布前的最低确认

在发布门禁中，以下角色必须都有已确认的负责人和备份账号；“待管理员指定”不能作为稳定版发布证据：

- 首席维护者与备份维护者：可以完成双人审阅、合并和紧急回滚；
- 安全响应协调人与备份：可以访问私密报告并完成无害收件演练；
- 发布负责人和备份：可以检查 draft Release、制品校验和、SBOM、构建证明并执行回滚；
- 数据库恢复负责人和备份：可以在隔离库完成恢复、核对和 RPO/RTO 记录；
- CI 与依赖负责人：可以处理必需检查、依赖告警和构建失败。

负责人确认应引用 GitHub 设置核验、运维演练或受控权限记录。缺少任何一个角色时，发布记录必须保留阻塞状态，并在发布说明中继续使用开发版口径。

## 新负责人加入

- [ ] 确认身份、职责范围和备份负责人。
- [ ] 按最小权限授予仓库、发布环境、CI 或备份系统权限。
- [ ] 阅读 [SECURITY.md](../../SECURITY.md)、[运行保障](../operations.md)、[发布与升级验收](../releasing.md) 和治理说明。
- [ ] 完成一次安全报告接收演练（使用无害测试内容）。
- [ ] 完成一次发布、回滚或数据库恢复演练中与职责相关的步骤。
- [ ] 确认凭据不共享，并记录轮换和撤销路径。

## 退出与交接

- [ ] 列出未完成的发布、迁移、恢复和安全事件。
- [ ] 将受控记录移交给接任人，不把安全细节写入公开 commit 或 issue。
- [ ] 撤销旧账号、token、SSH key、环境权限和 webhook secret。
- [ ] 验证备份负责人可以独立执行回滚或恢复。
- [ ] 更新本文件、`.github/CODEOWNERS`、GitHub 环境审批人和安全报告入口。
- [ ] 在交接记录中写明核验人、时间和证据位置。
