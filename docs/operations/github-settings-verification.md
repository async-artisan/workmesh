## 复核规则

- 仓库转移、默认分支变更、发布流程变更、维护者变更或安全事件后重新核验。
- 工作流文件的存在只能作为“实现线索”，不能替代 GitHub 管理页面上的实际状态。
- 证据中不得包含 token、Cookie、私钥、生产 URL 或未脱敏用户数据。

## 关闭条件与负面验证

一次设置核验只有在所有适用行都有“实际状态”、核验人、UTC 时间和证据位置后才能标记完成。除了检查设置页面，还应执行至少一项受控负面验证，并记录结果：

- 未经审阅的分支合并被拒绝；
- 非授权账号无法直接推送默认分支或创建受保护 tag；
- 未经环境审批的正式发布不会公开 Release；
- fork PR 和不受信任工作流不会读取生产密钥；
- 无害安全报告确实送达至少两名指定响应人员，且测试附件已清理。

若某项无法测试，实际状态必须保持“待核验”，并写明阻塞原因和下一步负责人。工作流源码、CODEOWNERS 文件或一次成功的 CI run 不能替代这些管理员设置和负面验证证据。
