# 运行边界与运维策略

## 知识库检索

检索默认返回 20 条、单页最多 100 条，并在应用层最多扫描 1000 个 chunk。可以通过
`RAG_MAX_CANDIDATES` 调整上限，但代码将其限制为 10000。响应中的 `truncated` 和 `metrics`
用于让调用方识别结果是否被截断以及本次候选、embedding 和排序耗时。

当前版本支持约不超过 100,000 个 chunk 的知识库；检索仍受应用层候选扫描上限约束。超过扫描上限时，`truncated`
标记会提示调用方结果仅基于已扫描候选，不能把截断结果当作完整召回。
保持 1000 的默认候选上限，直至本地基准验证显示需要调整。超过约 100,000 个 chunk，或截断率和 p95
持续超出业务目标时，应升级到专用向量数据库或检索索引。

扩容前用固定查询集和 1000、10000、50000、100000 chunks 数据集，分别测单请求与 20 并发；记录
端到端 p50/p95、候选数量、embedding/关键词耗时、截断率和进程内存。按实际 p95 与截断率决定是否
提高扫描上限或引入专用检索索引，不把数据集规模本身视为已支持能力。

关键词得分按查询词项覆盖率计算：中文按双字切分（单字查询保留原字），英文和数字按词切分，命中文档
标题额外加 0.5 权重，整串出现在正文时再加 0.25。最终得分为语义相似度 0.65 与关键词得分 0.35 的
加权和，低于 0.05 的候选被过滤。中文双字切分只解决"查询没有空格"的问题，语义排序仍取决于
embedding 模型质量。

## 知识库批量导入

```bash
pnpm --filter @workmesh/api db:import-kb -- --source=<知识库根目录> [--project-key=DEMO] [--name=知识库名称] [--dry-run]
```

脚本读取 `<source>/raw/prd/**/*.md`，按 `--name` 在目标项目下复用或新建知识库，每份文档的
`filename` 保留版本目录（如 `v1.1/PRD-财务模块.md`）。切块按一至三级标题进行，单块上限 1200
字符、过短块合并到 400 字符以上，块首带标题路径前缀，避免表格和章节被定长切片切断。

重跑以 `filename` 为幂等键：先删除该文档的旧块再写入。源目录中删除的文档不会自动清除，需要手工
删除对应文档。脚本只允许连接本地数据库；未配置 `OPENAI_API_KEY` 时使用本地哈希向量，链路可跑通
但语义检索质量有限，正式数据应配置真实 embedding 模型。

## 审计日志

默认保留 180 天。`pnpm --filter @workmesh/api db:audit-cleanup` 只做 dry-run 并输出待清理数量；
确认隔离数据库和影响范围后，追加 `--apply` 执行删除。保留天数可通过
`AUDIT_LOG_RETENTION_DAYS` 配置，脚本限制在 1 至 3650 天，并按 `created_at` 索引范围删除。

清理任务不在生产环境自动启用；部署方应使用受控定时任务，并保留 dry-run 输出和数据库备份策略。
