# WorkMesh 路线图

这是一份按证据和依赖排序的公开工作清单，不是带日期的承诺。完成一项功能不等于该能力已经成为官方支持；支持范围要以对应的验收记录、CI 运行和发布说明为准。

## 当前阶段：开发版收口

目标是让一个新使用者能够在受支持的环境中安装、跑通最小交付链路，并让维护者可以复核最终版本。

- 在同一个待发布 commit 上通过格式、类型、lint、单元、契约、集成、构建、浏览器和覆盖率门禁。
- 重跑当前全部数据库迁移，完成备份恢复、升级和失败回滚记录。
- 完成 Windows x64 draft 制品的新机安装、升级、卸载、校验和及内容检查。
- 补齐第二维护者、安全响应联系人、发布与恢复替补，以及 GitHub 私密报告、分支保护和必需检查的实际核验。
- 保留尚未具备证据的 GitHub live、生产容量、长期稳定性、Linux/macOS Box 和外部团队使用为明确阻塞项。

## 下一阶段：扩大可采用性

只有当前阶段的发布证据稳定后，才按用户反馈推进：

- Linux 和 macOS 的 Box 安装、服务管理、升级、备份恢复和卸载验收。
- 完整 Web 交付闭环、跨浏览器、键盘/焦点和辅助技术验收。
- 一个不参与实现的外部团队完成真实需求、交付、评审、发布和恢复，并留下脱敏记录。
- 真实 GitHub 仓库、PR/reviews 分页、Webhook 签名和提交级代码证据联调。
- 根据实际采用者需求决定是否发布 npm 包、增加其他制品或扩大平台支持。

## 之后再做的协议工作

这些项目已有设计或开发计划，但不应在实现前被描述为当前支持：

- Clarification / ClarificationResponse 和任务精确恢复协议。
- 更完整的 PRD 章节、原型 verify、产品与 QA 归档闭环。
- 多实例容量、灾备、外部指标聚合和长期运行基线。

## 如何影响路线图

Discussions 当前尚未由管理员启用；在启用前，请直接提交 [Feature request 模板](../../.github/ISSUE_TEMPLATE/feature.yml)，说明使用场景、问题和验收条件。涉及 API、数据库、认证、证据门禁或部署方式的提案，应同时写出兼容性、迁移、回滚和验证计划。维护者会根据用户影响、风险、实现成本和可复核证据调整顺序；路线图条目不构成实现或发布日期承诺。
