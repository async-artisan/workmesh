# 版本与兼容性口径

这份文档把“可以尝试”“已经验证”和“项目承诺”分开。每次发布若有不同口径，发布说明和[支持矩阵](../support-matrix.md)优先。

## 当前基线

- Node.js：20.19.0 或更高版本。
- pnpm：10.28.2，仓库通过 `packageManager` 固定。
- PostgreSQL：15+；CI 当前使用 PostgreSQL 16。
- 浏览器：Chromium 基础流程和 UI review 已有自动化；Firefox、WebKit、辅助技术和完整产品闭环仍需单独验收。
- 制品：当前发布流程只生成 Windows x64 draft Release；Linux、macOS、ARM 和 npm 包没有官方发布承诺。

平台适配器存在不代表该平台已通过安装、升级、服务管理、备份恢复和卸载验收。请在报告中附 OS、架构、Node、pnpm、PostgreSQL、浏览器、commit 和实际命令。

## 版本规则

- 版本和 tag 按 SemVer 形式管理；`-rc.N` 等预发布标识表示仍需人工验收。
- 根目录或包中的 `1.0.0` 字段不代表已经存在正式 Release。正式发布必须有对应 tag、制品、校验和、SBOM、构建来源证明和人工发布记录。
- 数据库 schema 变化必须包含迁移、升级顺序、回滚或恢复说明。使用者应在生产升级前备份，并在隔离库验证恢复。
- 角色包 manifest、共享错误码和 API 契约属于协同边界；不兼容变更应在 issue、变更记录和发布说明中说明影响。

## 弃用和支持

项目当前没有 LTS、固定安全响应 SLA 或历史版本自动回移承诺。计划弃用接口或配置时，维护者应在变更记录和发布说明中写明：替代方式、影响版本、迁移步骤、预计移除窗口和验证结果。安全修复的实际回移范围由维护者按影响评估决定。

若你依赖某个平台、API 或数据库升级路径，请先在 issue 中说明环境和所需支持期限；在发布说明明确承诺前，不要把社区成功运行当作官方兼容保证。
