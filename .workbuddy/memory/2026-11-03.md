### 已核实的关键缺陷（供后续修复）
1. **治理文档全缺**：CONTRIBUTING / SECURITY / CODE_OF_CONDUCT / CHANGELOG / ISSUE 模板 / PR 模板 / ADR 均不存在。
2. **文档事实漂移**：README 写迁移 0001–0011，实际 **0012**；`docs/deployment.md:31` 称「只有 0001_init」严重过时；`migration-plan.md` M3/M4/M5 迁移映射全错；根目录 `.env.example` 用 `JWT_SECRET`/`DATABASE_URL`，代码实读 `WORKMESH_V1_DATABASE_URL`；`code-wiki/ARCHITECTURE.md:217` 教跑已删除的 `workmesh init`；根目录 ARCHITECTURE.md 是 31B 指针空壳。
3. **覆盖率门禁未接线**：api vitest 配了 `thresholds.lines=80`，但 CI 跑 `vitest run`（无 --coverage），门槛从不生效。
4. **配置漂移（会致生产故障）**：代码读 `GITHUB_WEBHOOK_SECRET`，两处 .env.example 写 `GIT_WEBHOOK_SECRET`；`assertCookieDeployment` 只在 spec 调用，main.ts 启动未执行。
5. **依赖**：NestJS ^10.4.5、Prisma ^5.21.1 均 EOL；无 dependabot/audit；`multer`/`@nestjs/jwt`/`redis` 为死依赖。
6. **性能**：Web bundle 506.95 kB 未做代码分割（构建已告警）；零性能基准。
7. **验证空洞**：B3 浏览器 E2E、B2 GitHub live、B4 HTTP 契约套件（ERR_REQUIRE_ESM）均未解除。

### 项目自身优势（勿低估）
- 安全设计接近教科书：`__Host-` cookie、CSRF 双值 + timingSafeEqual、bcrypt 12 轮 + dummy hash、授权集中在 `v1-authorization.ts`（默认拒绝、404 不泄露存在性）、高风险动作一次性票据绑定 action/target/version/digest、webhook HMAC timing-safe 验签、SQL 全参数化。
- CI 含罕见的**数据库漂移闸门**（migrate deploy → migrate diff --exit-code）。
- `docs/positioning.md` 自我批判极强（R1–R7、G0–G4），已自认 R5「证据自指」与 R7 单人可维护性。
