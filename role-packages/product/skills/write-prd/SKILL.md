# 撰写 PRD

## 何时用

- 理解已确认，需要产出或修订 PRD。
- 已有 PRD 需要随变更升版。

## 结构

按 `prd` 模板产出，固定六节：

1. **背景**：为什么现在做，谁受影响。
2. **目标**：一句可验证的目标，不写愿景。
3. **范围**：做什么 / 不做什么，各列三条以内。
4. **方案要点**：只写约束与关键取舍，不写实现细节。
5. **依赖与约束**：涉及的单元、契约、外部系统、合规要求。
6. **验收**：指向 `acceptance.yaml`，正文不重复。

## 规则

- 不臆造需求：只写理解中已确认的内容，未确认的留在「未知项」。
- 每条关键结论标注依据（知识库条目 key、历史需求编号、决策记录）。
- 不写实现细节：接口、表结构、组件名属于技术方案，不属于 PRD。
- 范围必须可判定：出现「等」「相关」「类似」就展开或删掉。
- 一页能讲完；超过两页说明范围太大，回头拆需求。

## 与验收的分工

PRD 说「做什么、为什么」，验收说「怎么算完成」。两者分开写，验收由 `map-acceptance` 产出。

## 交接

产出 `prd.md` + `acceptance.yaml`，提交评审；QA 做可测性签核，产品负责人批准后发布。
