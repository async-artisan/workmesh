# 写设计规格

## 何时用

- 需求涉及新页面、新交互或视觉变更。
- 现有模式无法覆盖 PRD 的场景。

## 步骤

1. 读 PRD：目标、范围、验收，标出与界面相关的条目。
2. 查设计系统：能否用现有组件与模式组合。
3. 画页面与状态：正常、空、错误、加载、权限受限。
4. 写交互：点击、输入、校验、跳转、返回。
5. 标边界：长文本、超长列表、小屏、极端数据。
6. 产出 `design-spec.md`。

## 规则

- 每条界面相关的验收，都要有对应的界面表现。
- 五种状态缺一不可；只画正常态的设计不算完成。
- 不引入新组件，除非现有组件确实无法表达，并写明理由。
- 与既有设计规范不一致处，必须显式说明。

## 交接

`design-spec.md` 交产品确认、前端消费。前端据此实现，不必再猜。
