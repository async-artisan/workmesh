# 准备发布

## 何时用

- 需求进入发布候选，测试通过。
- 多服务存在发布顺序依赖。

## 步骤

1. 读 PRD 验收与发布范围，确认要发什么。
2. 列依赖：服务、数据库迁移、配置、第三方。
3. 定顺序：先发什么、后发什么、能否并行。
4. 定灰度：按用户、按流量、按租户，写清放量节奏。
5. 定监控：看哪些指标、阈值多少、谁来看。
6. 定回滚触发条件：什么情况必须退。
7. 产出 `release.md`。

## 规则

- 没有回滚触发条件的发布计划不算完成。
- 数据库迁移与代码发布分开：先兼容、再切换、后清理。
- 发布窗口与冻结线冲突时，走 hotfix 通道并记录。
- 依赖外部系统时，写清对方不可用时的降级。

## 交接

`release.md` 交发布评审；评审通过后进入 `rollback-plan`。
