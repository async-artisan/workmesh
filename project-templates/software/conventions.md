## 4. 注释

- 只写「为什么」，不复述「做了什么」。
- 公共函数必须有 JSDoc：用途、参数、返回、异常。
- TODO 必须带负责人和期限。
- 注释语言：中文；标识符与提交信息：英文。

```ts
// 好：兼容 2.x 客户端，3.0 全量后删除（zhang，2026-03）
if (legacyHeader) return fallback();

// 坏：设置 name
user.name = name;
```

## 5. 错误处理

- 错误码来源：
- 对外错误必须脱敏，不暴露堆栈与内部路径。
- 可重试与不可重试要区分，并写进契约。

## 6. 日志

- 级别约定：error / warn / info / debug 的使用边界。
- 禁止打印：密钥、token、完整连接串、个人信息。
- 请求日志必须带 requestId。

## 7. 测试

- 单测框架：
- 覆盖率要求：<不追 100%，但关键路径必须覆盖>
- 测试命名：`should_<行为>_when_<条件>`
- 禁止：跳过失败用例、改断言迁就实现。

## 8. 提交与 PR

- 提交信息：`<type>(<scope>): <描述> (<需求编号>)`
- 分支命名：`feat/<需求编号>-<简述>`
- PR 必须包含：改动范围、验收覆盖、回滚方式。

## 9. 依赖与安全

- 新增依赖需要说明理由与许可证。
- 禁止提交密钥、证书、`.env`。
- 依赖升级单独成 PR，不与功能混在一起。

## 10. 例外与豁免

需要偏离规范时：在 PR 描述里写明「偏离哪条、为什么、何时回归」。没有记录的偏离视为违规。
