# 消费契约

## 何时用

- 契约已发布，需要开工但后端未完成。
- 设计规格已可用，需要确定组件与状态。

## 步骤

1. 读契约：接口、入参出参、错误码、分页。
2. 读设计规格：页面、状态、交互、复用声明。
3. 列改动面：页面、组件、路由、状态管理、请求层。
4. 建 mock：按契约构造数据，覆盖正常、空、错误、加载。
5. 产出实现方案，写入 `impl.md`。
6. 老项目先核对现有组件、实际接口、工具配置与测试；技术取舍记录来源和备选，未决项显式保留。
7. 按可独立验证的业务场景拆实现，标出验收 key、依赖、负责文件和验证方式；只在前置满足且文件不冲突时并行。

## 规则

- 只信契约，不信「口头说会返回什么」。
- 契约缺字段就回问，不自行猜。
- mock 与契约同源：字段名、错误码必须一致。
- 复用优先：能用现有组件就不新造，偏离设计规范要写理由。

## 交接

`impl.md` 前半部分（改动范围、组件、接口依赖、mock 方案）交评审，然后进入 `implement-ui`。
