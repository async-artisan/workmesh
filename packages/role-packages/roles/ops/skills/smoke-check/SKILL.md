# 生产冒烟

## 何时用

- 发布完成，需要确认生产可用。
- 回滚后需要确认恢复。

## 步骤

1. 选冒烟范围：关键路径 + 本次变更涉及的验收。
2. 逐条执行：记录时间、结果、异常。
3. 看监控：错误率、延迟、关键业务指标。
4. 判定：通过 / 观察 / 回滚。
5. 产出 `smoke.md`。

## 规则

- 冒烟覆盖验收，不覆盖「我觉得重要」。
- 失败要立即分流：本次变更 / 环境 / 历史问题。
- 「观察」必须有观察人和时限，不能悬空。
- 回滚后同样要冒烟，确认真的恢复了。

## 交接

`smoke.md` 交发布确认；结论为「回滚」时立即执行 `rollback.md`。
