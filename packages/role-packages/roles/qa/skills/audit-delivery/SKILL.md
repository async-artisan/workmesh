# 核验交付完整性

1. 从任务快照取 PRD 与验收，读取本次实现提交、用例修订和执行环境；无法取得实际代码或结果就记录阻塞。
2. 逐条追踪 `验收 key → 任务 → 代码位置 → 用例 → 执行结果/证据`。任务勾选、用例设计覆盖和构建成功都不能代替行为证据。
3. 对每条验收记录已覆盖、部分覆盖、缺失、冲突、无法验证；区分实现缺口、失效用例、环境问题和新增范围。
4. 检查证据绑定同一 PRD、快照和 commit。可把映射填入 DELIVERY 质量包执行 `workmesh quality --file quality-bundle.json --json`；工具不下载引用、不读代码，也不判定功能通过。
5. 对缺口追加稳定 ID、验收 key、复现、受影响文件、建议负责人和复验条件。已有记录保留，重复发现关联原 ID，范围新增先走变更。
6. 产出 `delivery-audit.md`，作为当前任务允许的 CASES 正文或评审材料，交 HUMAN 决定返修、后续工作或正式验收。

## 边界

不自动执行修复循环、不覆盖历史结果、不修改其他角色工件、不批准。修复后只对受影响项复验，保留上一轮结论和版本；任何剩余阻塞都显式保留。
