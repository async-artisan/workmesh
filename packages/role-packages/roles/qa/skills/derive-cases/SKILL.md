# 派生用例

## 何时用

- PRD 已发布，验收条目可读。
- 验收修订后需要同步用例。

## 步骤

1. 逐条读验收，确认 `verification` 类型。
2. 每条验收至少一个用例；复杂条目拆成多个用例。
3. 写用例：`given / when / then` + 断言。
4. 标覆盖：`covers: [A1, A2]`。
5. 补边界与异常：空值、超长、并发、权限不足、下游失败。
6. 产出 `cases.yaml`。

## 规则

- 用例 ID：`TC-<需求编号>-<序号>`，例如 `TC-YFF-003-01`。
- 一条用例只验一个断言；多个断言会让失败原因变模糊。
- 不测实现细节：测行为与契约，不测内部函数。
- 失败必须能定位：写清前置状态与数据。
- 覆盖优先于数量：每条验收至少一个，不为凑数写重复用例。

## 与验收的对应

| 验收 verification | 用例形态                        |
| ----------------- | ------------------------------- |
| `TEST`            | 自动化用例，进回归              |
| `INSPECTION`      | 检查项 + 证据要求（截图、链接） |
| `DEMO`            | 演示步骤 + 预期观察             |

## 交接

产出 `cases.yaml`，交产品确认覆盖，交评审。覆盖缺口要显式列出，不藏着。
