# 执行评测

## 何时用

- 有可运行的构建或测试环境。
- 需要为某个提交 / 版本出一份可比较的结果。

## 步骤

1. 固定环境：构建版本、数据库版本、配置、依赖服务。
2. 选评测集：20–50 个真实任务，覆盖关键路径与高风险分支。
3. 执行：记录通过 / 失败 / 耗时 / 不稳定（flaky）。
4. 分类失败：
   - 产品缺陷
   - 用例问题（断言写错、数据过期）
   - 环境问题（依赖不可用、配置缺失）
5. 产出 `evals.yaml`。

## 规则

- 记录环境与版本；没有上下文的「全绿」不可信。
- 固定用例修订与实现版本；缺少可运行构建或环境时报告阻塞，不伪造执行结果。
- 测试结果是评审证据，最终验收由 HUMAN 在 Web 完成。
- 不掩盖不稳定：flaky 用例要标出来，不重跑到绿为止。
- 一次失败必须能复现；不能复现的记为「待观察」，不记为通过。
- 结果可比较：同一评测集跨版本对比，才看得出退化。

## 失败分类示例

```yaml
failures:
  - case: TC-YFF-003-04
    kind: PRODUCT_DEFECT
    evidence: 截图 + 日志
  - case: TC-YFF-003-07
    kind: CASE_INVALID
    reason: 断言仍按旧版契约编写
  - case: TC-YFF-003-09
    kind: ENVIRONMENT
    reason: 本地模型端口未启动
```

## 交接

产出 `evals.yaml` 与结果摘要，交评审。失败项按分类进入缺陷流程或修用例。
