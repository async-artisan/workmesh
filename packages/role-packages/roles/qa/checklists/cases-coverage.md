# 用例覆盖清单

- [ ] 每条验收至少一个用例。
- [ ] 用例 `covers` 引用的 key 在验收里存在。
- [ ] `kind` 与验收的 `verification` 一致。
- [ ] 边界覆盖：空值、超长、并发、权限不足。
- [ ] 异常覆盖：下游失败、超时、限流。
- [ ] 用例 ID 唯一，格式为 `TC-<需求编号>-<序号>`。
- [ ] 一条用例只验一个断言。
- [ ] 覆盖缺口已显式列出，并说明由谁、何时补。
- [ ] 不测实现细节，只测行为与契约。
- [ ] 评测集固定环境与版本，结果可跨版本比较。

## 交付前最后三问

1. 如果这条需求上线后出问题，现有用例能不能定位到哪个验收没过？
2. 有没有一条用例，删掉之后你依然有信心上线？如果有，它可能没用。
3. 失败分类写清楚了吗，还是全标成「产品缺陷」？
