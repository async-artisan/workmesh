# 契约质量清单

- [ ] 每个接口都写了用途、入参、出参、错误码。
- [ ] 出参只暴露调用方需要的字段，没有内部结构泄漏。
- [ ] 错误码复用优先；新增的写了含义与触发条件。
- [ ] 至少写了一条失败路径（超时 / 限流 / 下游不可用）。
- [ ] 数据变更带迁移与回滚，且回滚演练过。
- [ ] 兼容性结论明确：旧客户端是否受影响，是否需要平行变更。
- [ ] 下线旧版的条件写清了。
- [ ] 消费方（前端、QA、运维）与开工条件写清了。
- [ ] 契约与 PRD 的验收对得上，没有多做或少做。
- [ ] 契约里的字段命名与项目规范一致。

## 交付前最后三问

1. 前端只看这份契约，能不能不问问题就写代码？
2. 线上出问题时，这份契约能不能解释「应该是什么行为」？
3. 半年后要下线旧版，条件写得够清楚吗？
