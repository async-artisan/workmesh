# 后端角色包 · 技能索引

| 技能               | 做什么                                 | 何时用                 |
| ------------------ | -------------------------------------- | ---------------------- |
| `design-contract`  | 从 PRD 推导接口契约、数据变更与错误码  | PRD 就绪、开工前       |
| `plan-change`      | 调查现状、记录取舍、拆解任务及文件归属 | 老项目或复杂变更开工前 |
| `diagnose-bug`     | 原始复现、根因诊断、最小修复与复验     | 已有行为损坏时         |
| `implement-change` | 按契约实现并自测                       | 契约已发布、任务已认领 |
| `attach-evidence`  | 收集提交级证据并交付                   | 实现完成、准备交付     |

## 使用顺序

```
plan-change（按复杂度选择）→ design-contract → implement-change → attach-evidence
```

契约是并行开发的支点：前端、测试都靠它开工。**契约没发布之前，不要开始写实现**，否则前端只能猜。
已有行为损坏时从 `diagnose-bug` 进入，复用当前 PRD 和契约；按风险保留诊断、修复、原始复现结果，不强制重走新功能文档。

## 交接

- 契约 → `contract.md`，交前端、QA、运维消费；变更走平行变更。
- 实现 → `impl.md` + 提交引用，交评审。
- 交付 → `ArtifactSet` + `checks[]`，交人工验收。
