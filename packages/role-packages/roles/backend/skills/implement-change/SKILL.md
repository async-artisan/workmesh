# 实现变更

## 何时用

- 契约已发布，任务已认领。
- 需要在既有服务上做增量改动。

## 步骤

1. 取上下文：PRD 验收、契约、单元卡、项目规范。
2. 定位改动面：模块、接口、表、受影响调用方。
3. 编码：按契约实现，不擅自扩展接口。
4. 自测：正常路径、边界、错误路径、权限。
5. 提交：commit 正文带需求编号与任务编号。
6. 产出 `impl.md`。

## 规则

- 不臆造接口：契约里没有的字段不加；确实需要就回问，走变更。
- 不跳过迁移：数据变更必须带迁移与回滚方案。
- 注释只写「为什么」，不复述代码；TODO 带负责人和期限。
- 不改其他角色的工件：契约归后端，设计归 UI，验收归产品。
- 已知限制写进 `impl.md`，不隐藏。

## 自测清单

- [ ] 正常路径通过。
- [ ] 边界（空值、超长、并发）有覆盖。
- [ ] 错误路径返回约定错误码。
- [ ] 权限与鉴权未被放宽。
- [ ] 迁移可回滚，且演练过。

## 交接

产出 `impl.md` + 提交引用，交评审。评审通过前不进入 `DONE`。
