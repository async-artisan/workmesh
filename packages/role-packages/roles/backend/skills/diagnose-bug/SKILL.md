# 诊断与修复缺陷

1. 保存原报告、预期与实际行为、最小复现、版本和环境。不能复现时写条件与缺口，不先猜原因改代码。
2. 诊断阶段只读调查代码、日志和相关契约，区分产品缺陷、用例错误、环境问题与新增需求。
3. 记录根因证据、受影响模块、最小修复、回归风险及验证方案。已有范围与授权足够时继续修复；新增范围交现有变更流程决定。
4. 实现只修已定位原因，偏离计划留下依据。按风险补有意义的回归检查；相关测试通过后必须重跑原始复现。
5. 记录原始问题已复验、部分验证或仍失败，附实际命令与结果。测试套件全绿不能替代原始复现；缺环境不能写已修复。
6. 把诊断、修复、验证记录合并进 `impl.md`，交 QA 按 `audit-delivery` 复核和 HUMAN 验收。

小范围缺陷不强制重写完整 PRD；正式任务仍需当前基线、认领和交付，不绕过既有批准。
