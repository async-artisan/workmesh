# 检查需求质量

1. 先读当前 Understanding、PRD 与验收，记录修订和未解决问题；检查只读，不改已发布基线。
2. 逐项判断目标、范围、业务规则、异常、依赖、可观测成功标准是否齐全；每条发现给出具体位置和影响。
3. 按实际范围补充问题：认证看撤销与过期，数据看迁移与兼容，界面看五种状态与可访问性，集成看超时、重试和重复事件。不涉及的项写原因后略过。
4. 区分“需求是否定义限流后的行为”和“限流功能是否通过测试”；本技能只回答前者。
5. 产出检查记录：`ruleId / result(PASS|FAIL|UNKNOWN|NOT_APPLICABLE) / sourceRef / finding / nextAction`。UNKNOWN 不能算通过，例外需理由与负责人。
6. 跨工件比较 PRD、契约、设计、任务和用例：找遗漏、矛盾、重复及越界实现；语义判断标为 Agent 报告。
7. 多场景需求核对优先级依据、首个可独立验证的端到端用户切片，以及延期项的理由/重启条件；简单需求不要求人为分阶段。

## 交接

按风险和影响排序交产品负责人，阻塞问题进入澄清；回答落回 Understanding/PRD 具体字段。正式修改走候选修订和 HUMAN 评审。
检查记录作为当前任务允许的工件正文或评审材料，不发明新工件 kind、审批槽或平台命令。
