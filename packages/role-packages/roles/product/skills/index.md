# 产品角色包 · 技能索引

宿主应优先加载与当前任务匹配的技能，不要一次全读。

| 技能                 | 做什么                             | 何时用                         |
| -------------------- | ---------------------------------- | ------------------------------ |
| `clarify-intent`     | 把模糊诉求整理成目标、边界与未知项 | 需求刚提出、下游回问、范围不清 |
| `write-prd`          | 基于已确认理解产出 PRD             | 理解已确认、需要出稿或修订     |
| `map-acceptance`     | 把 PRD 拆成可判定的验收            | PRD 草稿完成、验收需修订       |
| `check-requirements` | 按风险检查需求质量与跨工件一致性   | PRD 评审前、变更范围扩大时     |
| `assess-idea`        | 用正反证据判断继续、澄清或停止     | 方向未定、需要比较投入时       |

## 使用顺序

```
clarify-intent → write-prd → map-acceptance → check-requirements
```

前一步的产出是后一步的输入。跳过 `clarify-intent` 直接写 PRD，通常会把未确认的假设写进需求。
方向未定先用 `assess-idea`，继续、澄清和停止均可形成有效记录；评估结束不自动启动实现。

## 交接

- 理解 → `understanding.md`，交产品确认。
- PRD → `prd.md` + `acceptance.yaml`，交评审批次。
- 验收 → 由 QA 做可测性签核后再发布。
