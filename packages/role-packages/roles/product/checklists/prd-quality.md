# PRD 质量清单

交付前逐条自检，未过的项写清原因，不隐藏。

- [ ] 背景能回答「为什么现在做」，不是「一直想做」。
- [ ] 目标是一句可验证的话，没有「提升体验」「优化流程」。
- [ ] 范围写了「不做什么」，且能挡住至少一个诱惑。
- [ ] 每条关键结论都有依据（知识库 key、历史需求、决策记录）。
- [ ] 没有把实现细节（接口、表结构、组件名）写进 PRD。
- [ ] 依赖与约束列了单元、契约、外部系统。
- [ ] 验收单独成文，正文没有重复条目。
- [ ] 每条验收都能写出一段会失败的检查。
- [ ] 验收里没有黑名单词（友好、快速、合理、尽量、优化、完善）。
- [ ] 验收条目 3–8 条；超过 15 条已拆需求。
- [ ] 未决问题都有责任人与阻塞标记。
- [ ] 全文一页到两页，超长已拆分。

## 交付前最后三问

1. 下游拿到这份 PRD，能不能不问问题就开始？
2. 如果只能实现一半，应该砍哪一半？PRD 里写了吗？
3. 三周后回来看，这份 PRD 还能判断「做没做完」吗？
